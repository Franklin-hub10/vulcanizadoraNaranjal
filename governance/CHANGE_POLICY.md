# Política de cambios

## Tipos de cambio

### Tipo A — Operativo

Ejemplos:

- nuevo precio;
- nuevo gasto;
- nuevo servicio;
- nueva actividad;
- actualización de un proceso;
- nuevo recurso;
- corrección de un dato.

Puede originarse con Joel o Franklin.

No requiere modificar gobernanza mientras pueda representarse con las reglas vigentes.

### Tipo B — Estructural operativo

Ejemplos:

- aparece una categoría de negocio no contemplada;
- se necesita un nuevo registro;
- se requiere relacionar entidades de una forma nueva;
- hace falta un nuevo apartado para documentar información real.

Joel puede originarlo. El organizador puede crear la estructura mínima necesaria siempre que no cambie reglas duras.

### Tipo C — Gobernanza

Ejemplos:

- cambiar roles;
- cambiar política de histórico;
- cambiar fuente canónica;
- cambiar reglas duras;
- cambiar política de auditoría;
- cambiar reglas de routing.

Requiere solicitud de Franklin.

## Flujo

1. Clasificar el cambio.
2. Verificar fuentes relacionadas.
3. Aplicar el cambio en el lugar canónico.
4. Actualizar referencias afectadas.
5. Registrar en histórico cuando sea relevante.
6. Si es Tipo C y lo solicita Joel, llevar a `PENDING_DECISIONS.md`.

## Correcciones

Corregir un error factual no equivale necesariamente a borrar el histórico.

- Si el valor previo era un error de captura y nunca fue válido, se corrige y se deja trazabilidad cuando sea material.
- Si el valor previo fue válido durante un periodo, se conserva como histórico.

## Eliminación

La eliminación permanente de información debe ser excepcional.

Preferir:

- marcar como histórico;
- marcar como archivado;
- registrar fecha de fin de vigencia.

## No duplicación

Antes de crear un nuevo archivo o concepto, comprobar si ya existe una fuente canónica adecuada.
