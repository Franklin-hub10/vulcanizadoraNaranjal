# Vulcanizadora Naranjal — Repositorio canónico del negocio

Este repositorio es la **fuente persistente de verdad** para organizar, documentar, consultar y evolucionar el conocimiento de Vulcanizadora Naranjal.

No es, por ahora, un proyecto de software tradicional. La interfaz principal de trabajo será un **organizador conversacional / Chat con acceso al repositorio**, y GitHub conservará la información validada, el histórico y las reglas que permiten interpretarla.

## Principio central

- **GitHub conserva el conocimiento.**
- **El Chat organiza, consulta, analiza y propone cambios.**
- **Franklin gobierna la estructura, reglas y modelo documental.**
- **Joel aporta y mantiene el conocimiento operativo del negocio.**
- Ningún dato operativo se inventa.
- Ninguna regla de gobernanza se modifica por una conversación operativa de Joel.
- El histórico relevante se conserva; no se reemplaza información pasada como si nunca hubiera existido.

## Actores

### Franklin — gobierno y estructura

Cuando el actor declara **"Soy Franklin"**, el organizador puede trabajar sobre:

- gobernanza;
- arquitectura documental;
- reglas del repositorio;
- taxonomía;
- criterios de registro;
- métricas y definiciones;
- estructura del backlog;
- políticas de cambio;
- nuevas capacidades del organizador;
- auditoría y mantenimiento del sistema documental.

Franklin también puede consultar y trabajar con información operativa.

### Joel — negocio y operación

Cuando el actor declara **"Soy Joel"**, el organizador se enfoca en:

- levantar cómo funciona actualmente el negocio;
- registrar servicios, actividades, precios, costos y gastos cuando Joel los informe;
- registrar información diaria, semanal o mensual;
- responder consultas usando la información vigente del repositorio;
- incorporar nuevos aspectos del negocio que Joel explique;
- crear, bajo las reglas existentes, nuevos apartados de conocimiento operativo cuando hagan falta;
- conservar el histórico de cambios de la operación.

Joel **no modifica la gobernanza base**. Si una necesidad operativa exige cambiar una regla estructural, se registra como propuesta o decisión pendiente para revisión de Franklin.

> La declaración de actor es contexto operativo para el organizador; no sustituye autenticación técnica o controles de permisos de GitHub.

## Fases de trabajo

1. **Gobernanza inicial** — definir reglas, roles, arquitectura documental y política de cambios.
2. **Levantamiento con Joel** — Joel explica cómo funciona realmente el negocio.
3. **Baselining** — convertir lo levantado en una estructura canónica: servicios, procesos, precios, costos, actividades, recursos, reglas de negocio y métricas.
4. **Operación continua** — registrar hechos y cambios reales.
5. **Análisis** — usar el histórico para indicadores, comparativos y proyecciones basadas únicamente en datos disponibles.

No se adelanta la fase 3 inventando servicios, precios, procesos o costos que Joel aún no haya explicado.

## Estructura inicial

- `BACKLOG.md` — punto de entrada y estado del trabajo.
- `governance/` — reglas duras y modelo de gobierno.
- `system/` — routing del organizador y reglas internas de resolución.
- `history/` — decisiones e hitos estructurales.
- Las áreas operativas del negocio se crearán después del levantamiento, cuando su estructura pueda basarse en información real.

## Fuente de verdad

Ante una consulta vinculada a Vulcanizadora Naranjal, el organizador debe:

1. identificar al actor cuando sea relevante;
2. consultar primero este repositorio;
3. priorizar información vigente y canónica;
4. usar el histórico cuando la consulta sea temporal o comparativa;
5. indicar cuando un dato aún no existe o no está validado;
6. no completar vacíos con supuestos presentados como hechos.
